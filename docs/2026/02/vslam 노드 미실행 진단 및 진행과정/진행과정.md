```bash
docker exec isaac_ros_dev-aarch64-container bash -c \
  'source /opt/ros/humble/setup.bash && \

```

```plaintext
isaac_ros_nitros_bridge_interfaces
```

💡 분석 및 조치
- **핵심 발견**: `isaac_ros_nitros`, `isaac_ros_gxf`, `isaac_ros_managed_nitros`, `isaac_ros_nitros_image_type`가 모두 누락되어 있었습니다.
- 이 패키지들은 `libvisual_slam_node.so`가 런타임에 링크하는 공유 라이브러리를 제공합니다.
- 누락 시 `component_container`가 VSLAM 플러그인을 `dlopen`할 때 실패하여 노드가 로드되지 않습니다.

- **근본 원인 확정**: Docker 컨테이너 재생성(`run_dev.sh`) 시 apt로 설치했던 패키지가 소멸되었으며, volume mount된 빌드 산출물(`libvisual_slam_node.so`)만 남아 있는 상태입니다.

## 10. rosdep 패키지 resolve 확인
누락된 패키지가 rosdep/apt를 통해 설치 가능한지 확인.

**명령어**
```bash
docker exec isaac_ros_dev-aarch64-container bash -c \
  'source /opt/ros/humble/setup.bash; \
   rosdep resolve isaac_ros_nitros 2>&1; echo "==="; \
   rosdep resolve isaac_ros_gxf 2>&1; echo "==="; \
   rosdep resolve isaac_ros_managed_nitros 2>&1; echo "==="; \
   rosdep resolve isaac_ros_nitros_image_type 2>&1'
```
**결과**
```plaintext
#apt
ros-humble-isaac-ros-nitros
===
#apt
ros-humble-isaac-ros-gxf
===
#apt
ros-humble-isaac-ros-managed-nitros
===
#apt
ros-humble-isaac-ros-nitros-image-type
```

💡 분석 및 조치
- 4개 패키지 모두 apt 패키지로 resolve 가능합니다.
- `rosdep install` 또는 직접 `apt-get install`로 설치할 수 있습니다.
- 사용자의 실행 절차에 `rosdep install`이 포함되어 있었지만, 컨테이너 재생성 후 NVIDIA apt 저장소 캐시가 초기화되어 설치에 실패했을 가능성이 있습니다.

## 11. NITROS 패키지 설치 후 재확인
apt install 실행 후 패키지가 정상적으로 설치되었는지 확인.

**명령어**
```bash
docker exec isaac_ros_dev-aarch64-container bash -c \
  'source /opt/ros/humble/setup.bash && \
   source /workspaces/isaac_ros-dev/install/setup.bash 2>/dev/null && \
   ros2 pkg list 2>/dev/null | grep -i "nitros\|gxf\|managed"'
```
**결과 (설치 후)**
```plaintext
gxf_isaac_atlas
gxf_isaac_gems
gxf_isaac_gxf_helpers
gxf_isaac_message_compositor
gxf_isaac_optimizer
gxf_isaac_sight
isaac_ros_gxf
isaac_ros_managed_nitros
isaac_ros_nitros
isaac_ros_nitros_bridge_interfaces
isaac_ros_nitros_image_type
isaac_ros_nitros_tensor_list_type
```

💡 분석 및 조치
- NITROS/GXF 관련 패키지가 모두 정상 설치되었습니다.
- `isaac_ros_nitros`, `isaac_ros_gxf`, `isaac_ros_managed_nitros`, `isaac_ros_nitros_image_type` 4개 핵심 패키지와 GXF 하위 모듈까지 확인됩니다.
- 이 상태에서 VSLAM launch를 실행하면 `libvisual_slam_node.so`가 필요한 공유 라이브러리를 모두 찾을 수 있어 플러그인 로드가 성공합니다.

## 결론

| 항목 | 내용 |
|---|---|
| **근본 원인** | `run_dev.sh`로 Docker 컨테이너 재생성 시 apt 설치 패키지(NITROS/GXF)가 소멸 |
| **누락 패키지** | `isaac_ros_nitros`, `isaac_ros_gxf`, `isaac_ros_managed_nitros`, `isaac_ros_nitros_image_type` |
| **실패 증상** | `component_container`가 `VisualSlamNode` 플러그인 dlopen 실패 → 노드 미로드 |
| **해결** | Docker 내부에서 `sudo apt-get install -y ros-humble-isaac-ros-nitros ros-humble-isaac-ros-gxf ros-humble-isaac-ros-managed-nitros ros-humble-isaac-ros-nitros-image-type` |
| **영구 대책** | Dockerfile 또는 `.isaac_ros_common-config`에 패키지 설치 명령 추가 |
